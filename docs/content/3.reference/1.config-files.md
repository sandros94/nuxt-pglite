Both files default-export the result of their define helper. The helpers are identity functions that infer the extensions and mark the config with its side: a server config loaded as the client one, or the reverse, fails at load with a pointer to the right helper.

## `server/pglite.config.ts`

```ts
definePGliteServerConfig(config: PGliteConfig<E> & EnvOverrides<PGliteConfig<E>>)
```

`definePGliteServerConfig` is auto-imported on the server; it is `definePGliteConfig` from `nuxt-pglite/core` under its Nuxt name.

| Key | Type | |
| --- | --- | --- |
| *PGlite options* | `PGliteOptions<E>` | `dataDir`, `extensions`, `debug`, `relaxedDurability`, `username`, `database`, … ([reference](https://pglite.dev/docs/api#options)). |
| `init` | `(pg) => void \| Promise<void>` | Runs once per created instance, before it is handed out. |
| `dispose` | `(pg) => void \| Promise<void>` | Runs before the instance is closed through its provider. |
| `devtoolsActions` | `PGliteServerAction<E>[]` | [Server actions](/guide/devtools/actions#server-actions). |
| `$development` / `$production` / `$test` | `Partial<PGliteConfig<E>>` | Shallow overrides for that environment; `$test` wins while testing. |

`pg` is `PGliteInstanceFor<PGliteConfig<E>>`: a `PGlite` with the namespaces your extensions add.

## `app/pglite.config.ts`

```ts
definePGliteClientConfig(config: PGliteClientConfig<E, C> & EnvOverrides<PGliteClientConfig<E, C>>)
```

`definePGliteClientConfig` is auto-imported in the app, and provided as a global in the worker bundle.

| Key | Type | |
| --- | --- | --- |
| *PGlite worker options* | `PGliteWorkerOptions` | `dataDir`, `debug`, `relaxedDurability`, `id`, `meta`, … |
| `extensions` | `E` | Postgres extensions, loaded in the worker. |
| `clientExtensions` | `C` | Extensions that add a namespace (`live`, `electricSync`), loaded on the main thread and typed on the instance. |
| `init` | `(pg) => void \| Promise<void>` | Runs once in each tab that creates the instance. |
| `dispose` | `(pg) => void \| Promise<void>` | Runs before the instance is closed through its provider. |
| `devtoolsActions` | `PGliteClientAction<C>[]` | [Client actions](/guide/devtools/actions#client-actions). |
| `$development` / `$production` / `$test` | `Partial<PGliteClientConfig<E, C>>` | Shallow overrides for that environment. |

`pg` is `PGliteClientInstanceFor<…>`: a `PGliteWorker` with the namespaces your `clientExtensions` add.

## Actions

```ts
interface PGliteAction<Ctx> {
  id: string // unique among the actions of the same kind
  label: string
  description?: string
  run(ctx: Ctx): unknown // the result is shown in DevTools, reduced to JSON
}
```

| Type | Context |
| --- | --- |
| `PGliteServerAction<E>` | `{ pg }`, the server instance |
| `PGliteClientAction<C>` | `{ pg }`, the app's worker instance |
| `PGliteSocketAction` | `{ socketUrl, env, dataDir?, startSubprocess, terminal, logger }`, in [`pglite.socket.devtoolsActions`](/reference/socket-options) |
