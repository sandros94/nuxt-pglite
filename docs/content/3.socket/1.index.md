While `nuxt dev` runs, the module can serve your server-side PGlite over TCP. Drivers, ORMs, migration tools and `psql` connect to it as they would to any Postgres server, so your code needs no PGlite-specific branch.

```ts [nuxt.config.ts]
export default defineNuxtConfig({
  pglite: {
    server: {
      socket: { port: 5433 }, // or `true` for a free port
    },
  },
})
```

```bash [Terminal]
✔ PGlite socket listening at postgres://postgres@127.0.0.1:5433/postgres (DATABASE_URL)
```

The socket only runs in `nuxt dev`. It is created in the Nuxt process from your [server config](/server#the-config-file), so it survives server reloads; a change to the config file restarts Nuxt.

## Finding the URL

The URL is available in three ways:

- **`DATABASE_URL`**: set to the socket's URL when it is still unset, so a real database configured in your environment always wins. `socket.env` renames the variable, or disables it with `false`.
- **`useRuntimeConfig().pglite.url`**: on the server, for code that should not read `process.env`.
- **The terminal**: the URL is printed when the socket starts. Pin `port` so that tools outside Nuxt can rely on it.

```ts [nuxt.config.ts]
export default defineNuxtConfig({
  pglite: {
    server: {
      socket: { port: 5433, env: 'PGLITE_URL' }, // `env: false` sets no variable
    },
  },
})
```

## Connecting

The socket speaks the Postgres protocol, so use the driver you would use in production.

::code-group

```ts [Drizzle]
// server/utils/db.ts
import { drizzle } from 'drizzle-orm/node-postgres'

export function useDB() {
  return drizzle(process.env.DATABASE_URL!)
}
```

```ts [pg]
// server/utils/db.ts
import pg from 'pg'

const pool = new pg.Pool({ connectionString: process.env.DATABASE_URL })

export function useDB() {
  return pool
}
```

```ts [postgres.js]
// server/utils/db.ts
import postgres from 'postgres'

const sql = postgres(process.env.DATABASE_URL!)

export function useDB() {
  return sql
}
```

::

### Tools outside the app

Tools that run in their own process reach the same database through the pinned port:

::code-group

```ts [drizzle.config.ts]
import { defineConfig } from 'drizzle-kit'

export default defineConfig({
  schema: './server/database/schema.ts',
  dialect: 'postgresql',
  dbCredentials: {
    url: process.env.DATABASE_URL ?? 'postgres://postgres@127.0.0.1:5433/postgres',
  },
})
```

```bash [psql]
psql postgres://postgres@127.0.0.1:5433/postgres
```

::

With `nuxt dev` running, `drizzle-kit push`, `drizzle-kit studio` or `psql` work against PGlite. To launch them from Nuxt DevTools with the URL filled in, use a [`process` action](/devtools/actions#process-actions).

::note
Connections are not authenticated: any user name and password are accepted, and every database name reaches the same database. The socket listens on `127.0.0.1` by default.
::

## Server instance and socket together

The socket's instance holds the configured data directory, and PGlite allows one instance per directory. With both the server side and the socket enabled, connect to the socket from your routes too (that is what the snippets above do), rather than calling `usePGlite()`, which refuses the directory the socket serves. See [Advanced](/server/advanced#when-the-socket-is-running) for the alternative.

If PGlite is only your development database, disable the server side altogether: that is the next page.
