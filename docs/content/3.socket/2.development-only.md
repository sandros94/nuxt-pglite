The most common setup: PGlite replaces the local Postgres you would otherwise install, run or containerise, while production uses a real database. The socket does not depend on the server side, so you can disable the latter:

```ts [nuxt.config.ts]
export default defineNuxtConfig({
  modules: ['nuxt-pglite'],
  pglite: {
    server: {
      enabled: false, // no `usePGlite()`, nothing of PGlite in the build
      socket: { port: 5433 }, // but a Postgres URL while `nuxt dev` runs
    },
  },
})
```

- In `nuxt dev`, the socket starts and sets `DATABASE_URL` to its own URL.
- In production, `DATABASE_URL` comes from your host, and the build contains your driver only.

Your database code reads `DATABASE_URL` and nothing else.

::steps{level="3"}

### Read `DATABASE_URL`

```ts [server/utils/db.ts]
import { drizzle } from 'drizzle-orm/node-postgres'

import * as schema from '../database/schema'

export function useDB() {
  return drizzle(process.env.DATABASE_URL!, { schema })
}
```

```ts [server/database/schema.ts]
import { pgTable, serial, timestamp } from 'drizzle-orm/pg-core'

export const visits = pgTable('visits', {
  id: serial('id').primaryKey(),
  createdAt: timestamp('created_at', { withTimezone: true }).notNull().defaultNow(),
})
```

### Prepare the development database

The socket still reads `server/pglite.config.ts`, so `init`, extensions and per-environment settings apply to the development database:

```ts [server/pglite.config.ts]
export default definePGliteServerConfig({
  init: async (pg) => {
    await pg.exec(`
      CREATE TABLE IF NOT EXISTS visits (
        id serial PRIMARY KEY,
        created_at timestamp with time zone NOT NULL DEFAULT now()
      )
    `)
  },
})
```

Or skip `init` and push the schema with your migration tool, against the socket while `nuxt dev` runs:

```ts [drizzle.config.ts]
import { defineConfig } from 'drizzle-kit'

export default defineConfig({
  schema: './server/database/schema.ts',
  dialect: 'postgresql',
  dbCredentials: {
    // the real database when DATABASE_URL is set, the socket otherwise
    url: process.env.DATABASE_URL ?? 'postgres://postgres@127.0.0.1:5433/postgres',
  },
})
```

```bash [Terminal]
npx drizzle-kit push
```

### Use it in routes

```ts [server/api/visits.post.ts]
import { count } from 'drizzle-orm'

import { visits } from '../database/schema'

export default defineEventHandler(async () => {
  const db = useDB()
  await db.insert(visits).values({})
  const [{ total }] = await db.select({ total: count() }).from(visits)
  return { total }
})
```

### Deploy with a real `DATABASE_URL`

Set `DATABASE_URL` in your host's environment to any Postgres: Neon, Supabase, Railway, a managed instance or your own server. Run your migrations against it the same way (`DATABASE_URL=… npx drizzle-kit push`). See [Deploy](/deploy) for a complete example.

::

## Try it

This documentation site is built this way. The demo below calls `/api/visits`, a route that uses Drizzle over `DATABASE_URL`. In `nuxt dev` it reaches PGlite through the development socket; on the deployed site it reaches whatever database `DATABASE_URL` points to, and tells you so when there is none.

:pglite-server-demo

```ts [server/utils/db.ts]
import { drizzle } from 'drizzle-orm/node-postgres'
import type { NodePgDatabase } from 'drizzle-orm/node-postgres'

import * as schema from '../database/schema'

let db: NodePgDatabase<typeof schema> | undefined

/** `undefined` when there is no `DATABASE_URL`, so the routes can say so. */
export function useDB() {
  const url = process.env.DATABASE_URL
  if (!url) {
    return undefined
  }
  db ??= drizzle(url, { schema })
  return db
}
```

## What ends up where

| | `nuxt dev` | Production build |
| --- | --- | --- |
| `DATABASE_URL` | the socket's URL, unless already set | your host's value |
| `server/pglite.config.ts` | loaded by the socket | not bundled |
| `@electric-sql/pglite` in the server output | n/a | absent |
| `usePGlite()` / `#pglite/server` | a stub that rejects with a pointer | a stub that rejects with a pointer |

::tip
The socket imports the server config file in the Nuxt process, outside any bundle. `definePGliteServerConfig` is provided there even with the server side disabled; other imports must be packages or relative paths, since Nuxt aliases (`~`, `#imports`, …) do not resolve outside a bundle.
::
