This documentation site is a Nuxt app using Nuxt PGlite, deployed on Netlify. Its setup is the [PGlite in dev, Postgres in prod](/socket/development-only) recipe plus an in-browser instance for the examples:

```ts [docs/nuxt.config.ts]
export default defineNuxtConfig({
  modules: ['nuxt-pglite'],
  pglite: {
    client: { enabled: true }, // the interactive examples
    server: {
      enabled: false, // nothing of PGlite on the server
      socket: { port: 5456 }, // `DATABASE_URL` while `nuxt dev` runs
    },
  },
})
```

## What ends up in the build

| | Server output | Client output |
| --- | --- | --- |
| PGlite engine and WebAssembly | absent (`server.enabled: false`) | present, loaded in a worker on first use |
| `server/pglite.config.ts` | absent: only the socket reads it, in `nuxt dev` | absent |
| `app/pglite.config.ts` | absent | present |
| Your driver (`pg`, Drizzle, …) | present | absent |

The server routes only know `DATABASE_URL`. Nothing else changes between development and production.

## Steps

::steps{level="3"}

### Add a `netlify.toml`

Netlify detects Nitro, which picks its `netlify` preset by itself. In a monorepo, point the build at the app's directory:

```toml [netlify.toml]
[build]
  base = "docs"
  command = "pnpm build"
  publish = "dist"

[build.environment]
  NODE_VERSION = "24"
```

`publish` is relative to `base`: the `netlify` preset writes the static files to `dist` and the server to `.netlify/functions-internal`. For an app at the root of its repository, drop `base`.

### Set `DATABASE_URL`

In the Netlify UI, under **Site configuration → Environment variables**, add `DATABASE_URL` with your production database's connection string, scoped to **Functions** (the server routes read it at runtime).

Any Postgres reachable from Netlify works: [Neon](https://neon.tech), [Supabase](https://supabase.com), [Railway](https://railway.com), a managed instance or your own server. Use the pooled connection string when your provider has one: serverless functions open many short-lived connections.

### Prepare the database

Apply your schema to the production database the way you applied it to the socket:

```bash [Terminal]
DATABASE_URL="postgres://…" npx drizzle-kit push
```

### Deploy

Push to the branch Netlify builds, or run `netlify deploy --build`.

::

Without `DATABASE_URL`, the site still deploys and every page works; the routes that need the database answer with a "no database configured" message. The demo on [PGlite in dev, Postgres in prod](/socket/development-only#try-it) shows which case this deployment is in.

## Other platforms

The same pattern works on any host Nitro supports (Vercel, a Node server, a container…): the build contains your driver and reads `DATABASE_URL`, the host provides it. Only the build settings differ; see [Nuxt's deployment guide](https://nuxt.com/docs/getting-started/deployment).

If you deploy with the server side **enabled**, PGlite itself runs in production and needs a writable, persistent data directory: a Node server or a container with a volume, not a serverless function. Set it with [`NUXT_PGLITE_DATA_DIR`](/server/options#runtime-overrides).
